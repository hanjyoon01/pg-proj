# Spec 01 — 참고 PG 규격 선정

상태: 확정 (2026-11-22). 규격 선정은 이 문서에서, 세부 계약(필드·상태·에러·웹훅·멱등성)은 `02-toss-api-contract.md`에서 공식 문서 기준으로 정리했다.
근거: `docs/intent/payment-portfolio.md`

## 결정

- **기준 규격: 토스페이먼츠 단일.** 모의 PG의 API 형태, Payment 객체, 상태 전이, 웹훅, 에러 코드는 토스페이먼츠를 따른다.
- 어댑터 인터페이스(`PaymentGateway`)도 토스 모델을 기준으로 추상화한다. 나중에 실제 PG 샌드박스 어댑터로 교체 가능해야 한다.
- 포트원 V2, Stripe는 규격으로 참고하지 않는다. (필요해지면 별도 결정으로 추가)
- 예외: 토스 문서에 동작이 없는 "같은 멱등키 + 다른 본문"은 Stripe의 동작을 참고해 422로 거부하기로 했다(`02`의 7-0절). 규격 전체를 따르는 것은 아니다.

## 모의 PG 범위

포함
- 카드 결제 승인 (confirm)
- 전체 취소 / 부분 취소 (cancel)
- 결제 조회 (paymentKey, orderId 기준)
- 웹훅 발송 (결제 상태 변경 이벤트)
- 멱등성 키 처리 (`Idempotency-Key` 헤더)
- 장애 주입: 타임아웃, 응답 유실, 중복 웹훅, (선택) 웹훅 순서 뒤바뀜

제외
- 가상계좌, 간편결제, 빌링(정기결제), 에스크로
- 카드 인증 화면 (클라이언트 인증 단계는 스텁으로 대체)
- 실제 PG 샌드박스 연동 (후순위)

## 참고할 토스페이먼츠 요소 (상세 내용과 검증 결과는 `02-toss-api-contract.md`)

| 영역 | 참고 내용 |
|---|---|
| 승인 | `paymentKey`, `orderId`, `amount`를 서버에서 승인 요청. 금액 위변조 검증 |
| 취소 | 전체·부분 취소, 취소 사유, 취소 이력(`cancels`) |
| 상태 | `READY`, `IN_PROGRESS`, `DONE`, `CANCELED`, `PARTIAL_CANCELED`, `ABORTED`, `EXPIRED` |
| 웹훅 | 상태 변경 이벤트, 재전송, 수신 측 재조회 검증 |
| 멱등성 | `Idempotency-Key` 헤더 동작 |
| 에러 | `code`, `message` 구조와 에러 코드 체계 |

## 미결 사항 (해소 현황)

- 토스 공식 문서 기준 필드·상태·에러 코드 목록 → `02`에서 정리 (상태 전이 흐름도 원문 대조는 `02`의 8절에 남음)
- 웹훅 서명 검증 방식 → 모의 PG가 HMAC-SHA256으로 서명하고 우리가 검증 (카드 웹훅에 토스가 실제로 서명하는지는 미확인, `03`의 4-7절)
- 멱등성 키 보관 기간과 충돌 처리 정책 → 15일, 다른 본문은 422 (`02`의 7-0절, `03`의 4-6절)
